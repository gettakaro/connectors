# ARK native Generic sidecar

This sidecar connects Takaro's Generic WebSocket to the exact-build ARK native loopback API. It needs `ARK_NATIVE_TOKEN` and the usual Takaro registration credentials. The native API defaults to `http://127.0.0.1:18891` and is required to return real game state. The sidecar exposes its own health endpoint on `127.0.0.1:18892`.

The sidecar maps `testReachability`, player and inventory reads, item and entity catalog reads, and `sendMessage` to authenticated native endpoints. `getPlayer` returns JSON `null` for an unknown or offline Steam64 ID. `getPlayerLocation` requires finite numeric `{x,y,z}` coordinates. Inventory stacks require a verified item `code`, `name`, and positive integer `amount`; unavailable native data is an error, never an invented empty result. `listEntities` reads all bounded native `/entities` pages and requires unique, nonempty DinoNameTag codes and display names before returning a catalog. `listLocations` reads one complete `/locations` snapshot of loaded APlayerStart actors and requires native rectangular bounds (`position`, `sizeX`, `sizeY`, `sizeZ`); a bare point or invented radius is rejected. Broadcast `sendMessage` posts raw UTF-8 to `/message`. Targeted messages require an unambiguous Steam64 in `opts.recipient.gameId` (or its `steamId`/`platformId` aliases) and post to `/players/:Steam64/message`; an invalid or unavailable recipient never falls back to broadcast. A message succeeds only after the native game-thread route returns `{success:true}`. The loaded spawn-point route, targeted message, and entity catalog still require their respective live verification.

For event enrichment after an outage, the native location route can return the latest actual departure position of an offline player, or a retained death position before a new pawn is observed. These snapshots remain bounded by the native event ring. A fresh live position takes priority; a newer departure without a captured position does not reuse an older departure. Native JSON labels these results with `source: departure` or `source: death`; Takaro's position DTO contains only coordinates. Its location request has no event sequence, so this is current or last-known position data, not a guarantee of the exact position when each queued event occurred. It does not make an offline player appear in the roster or permit actions against a departed actor.

Native `chat-message`, `player-connected`, `player-disconnected`, `player-death`, and verified `entity-killed` events are forwarded with their native player and timestamp. An entity kill uses the validated DinoNameTag catalog code and sends `weapon:''` when the native game cannot identify a weapon; an empty string means unknown, not an item. Narrow native `log` events carry only bounded, safe game-engine save/startup diagnostics and have no player. The sidecar rejects log messages with credential or address markers. Live entity-kill and log-hook acceptance remain pending. The cursor stores both native boot ID and confirmed sequence. A WebSocket pong confirms ordered transport delivery, not Takaro's per-event application acceptance. On a WebSocket disconnect, unconfirmed events are replayed from the native ring and may duplicate an event Takaro already received; a ring truncation is logged as data loss. There is no RCON or cached-game-data fallback.

Run `npm ci && npm run build && npm test` from this directory. The container must share the game server's network namespace so `127.0.0.1:18891` reaches the native listener. Configure `TAKARO_CURSOR_FILE` on persistent storage for restart replay.
